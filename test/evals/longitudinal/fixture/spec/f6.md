Feature request 6: waiting list.

- `book ... --wait` (single bookings only: with `--repeat` it is exit 1). When the booking cannot be made only because of a conflict, the request goes on the room's waiting list instead: exit 0, and it prints the request with `"status": "waiting"` and an id taken from the booking id counter. An invalid request still fails with exit 1. When there is no conflict, `--wait` books as usual.
- When a cancellation frees time in a room, that room's waiting requests are checked in the order they were made. Each request that no longer conflicts with a confirmed booking, and still lies within the room's current opening hours, becomes confirmed with the same id. The requests after it are checked against it. A request that cannot be confirmed stays on the waiting list unchanged.
- `bookings` lists confirmed bookings only. `waitlist [--room ROOM]` prints the waiting requests in the order they were made.
- `cancel ID` on a waiting request removes it from the waiting list (its status becomes `cancelled`).
